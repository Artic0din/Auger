# Silo `/api/v2` contract (vendored)

`SOURCE` pins the API v2 contract to `silo-server` commit `feae205be9fc7bf2f78f79a023cd3805b63a94ac` (which adds optional integer `ProfileCollection.max_profiles`; published `list_profiles_ok.json` omits it, so decoder tests cover both presence and omission).
All response fixtures and Settings subsets retain the `cc8514943289045e7b9f7ac8d36d4968bfe93926` snapshot (except `request_status_ok.json` below) to avoid unrelated upstream fixture churn.
For the complete per-operation table, auth headers, and retry behavior, see [docs/native-api-v2.md](../../../docs/native-api-v2.md).

## Updating the pinned contract

1. Run `SILO_SERVER_REPO=/path/to/silo-server scripts/sync-apiv2-fixtures.sh <server-ref>` to re-vendor fixtures, rebuild both Settings subsets in manifest order, and rewrite `SOURCE`.
2. Update the Settings manifest revision and SHA-256 below if the script prints new values, re-check the audio-ordinal invariants in `silo-server` (`internal/catalog/detail.go`, `internal/apiv2/catalog_items.go`, `internal/api/handlers/playback_v3.go`), and update affected decoders in `src/contracts/v2/`.
3. Run `npm run test:native` and `bash scripts/sync-apiv2-fixtures.test.sh` and confirm both pass.

## Vendoring rules and pinned manifest

- `fixtures/` holds response bodies copied unchanged from `contracts/api/v2/fixtures/` at the retained snapshot (`cc851494`), with three exceptions managed by `scripts/sync-apiv2-fixtures.sh`:
  - `settings_contract_ok.json`: nine definitions unchanged from `contracts/settings/v1/manifest.json` at the retained snapshot (v1, revision 24, SHA-256 `95b716c8b34974e4b97ee96f5c644135c437e09f4a6f2285fb263e3351e6c6ea`): `ui.disabled_library_ids`, `playback.audio_language`, `playback.preferred_quality`, `playback.max_bitrate_kbps`, `player.video_skip_back_seconds`, `player.video_skip_forward_seconds`, `player.audiobook_skip_back_seconds`, `player.audiobook_skip_forward_seconds`, and `ui.title_art`, plus `playback_audio_languages`.
  - `settings_rows_216.json`: eight additional TV-capable Settings definitions (`SETTINGS_ROWS_KEYS`) and `catalog_metadata_languages` from the same manifest.
  - `request_status_ok.json` (`KEPT`): copied unchanged from `silo-server` `6e8c68d036fd32c4ec7fe1d328f8286d4a164e60` (newer than the retained snapshot) for `remove_failed_supported`; move into `SELECTED` once the fixture snapshot advances past it.
- `wire.ts` decodes only consumed fields, ignores unknown members, and decodes unknown enum values to `"unknown"` so additive server changes stay compatible. Malformed consumed fields fail with a `WireError` path and omit offending values.

## Decoder invariants and additive extensions

- **Password sign-in and profiles (`wire.ts`):** `login_ok`, `login_invalid_credentials`, `login_account_required`, `login_password_required`, and `list_auth_providers_ok` come from the retained snapshot. Refusals follow `internal/apiv2/auth.go`: 401 `invalid_token`, 403 `local_login_disabled`/`not_permitted`/`password_expired`/`account_required`, 409 `email_in_use`/`identity_linked_elsewhere`, 429 `rate_limited`, and 503 `dependency_unavailable`, using Apple's `LoginViewModel.message` copy. `listProfiles` decodes optional integer `ProfileCollection.max_profiles` (pinned at `SOURCE`).
- **Settings (`settings.ts`):** `player.hdr_enabled` is accepted from a live contract when its device-only boolean definition matches (`player.dolby_vision_enabled` stays unread); neither is in the vendored subset. Title art requires settings API v1, manifest revision 16+, and both `profile` and `profile_device` scopes ([title-art.md](../../../docs/features/title-art.md)).
- **Catalog, discovery, and box sets (`catalog.ts`, `discovery.ts`, `boxSets.ts`):** handwritten from `openapi.json` at the retained snapshot, with newer additions noted here. Optional `extras` and `videos` default to empty lists (`is_official` missing defaults to `false`; non-boolean fails). Optional `OverlayConfig.images` and `user_state.watched_count`/`unplayed_count` follow `silo-server` `3f1081bdfe82285ede3925473a1d63bb197e68f5` (newer than the retained snapshot). Discovery queries retain `window_cursor` and `effective_sort`, accept limits 1–100 (1–200 for collection items) and seek positions 0–10000000. Search consumes strict optional booleans `video_with_episodes_scope` and `box_sets` ([Text Search](../../../docs/features/skyline-browse-shell.md#text-search)); box-set responses are not hand-copied into `fixtures/`.
- **Playback and tracks (`playback.ts`, `src/api/audioPreferenceOperations.ts`, `src/api/subtitlePreferenceOperations.ts`):** `effective_media_file_id` is decoded as an opaque string. The subtitle inventory is an authoritative combined ordinal space; echo `track_id` directly. Audio IDs `file:{effectiveFile}:audio:{n}` index the version's `audio_tracks` ordinal (re-verify the three `silo-server` files above whenever `SOURCE` advances). Quality choices follow `available_qualities` in server order with local `Auto` prepended and legacy `Original` omitted. Preplay audio/subtitle preferences persist via `PUT`/`DELETE /audio-prefs/{key}` and `/subtitle-prefs/{key}` ([preplay behavior](../../../docs/features/skyline-browse-shell.md#preplay-audio-subtitles-and-resume)); quality rules live in [playback-quality.md](../../../docs/playback/playback-quality.md).
- **Audiobooks (`audiobooks.ts`, `src/api/audiobookOperations.ts`):** exposes `listAudiobookGroups` (read, limit 1–200), `getAudiobook` (`getCatalogItem`), `queryAudiobooks` (`queryCatalogItems`, `natural_idempotent`, scoped by `library_id` with no `type`), and `syncProgress` (`non_retryable`, caller passes `replayAfterRefresh: false`, whole-book ms with `force_overwrite`). Accepts `"audiobooks"` and `"audiobook"` library types; `nav.show_audiobooks` is `client_local` (never sent to the Server). Parts match `presentation_kind: "audiobook_part"` or audio/duration metadata, ordered by `presentation_part_index` then numeric `file_id`, falling back to `"Part N"` when chapterless and unnamed. A part without `duration` sizes from its furthest chapter `end_seconds`; a multi-part book with any unknown part length is rejected. Timeline helpers (`playerStartPosition`, `chapterAt`, `relativeSeekTarget`) map `user_data` (30 s resume grace, 5 s end margin, finished flag) and chapter/seek positions onto the stitched timeline, while `StartPlaybackBody.progress_persistence: "client"` and optional `ClientCapabilities.max_resolution` support audio-only V3 starts.
- **Playback markers (`markers.ts`, `src/api/markerOperations.ts`):** reads `GET /markers/files/{file_id}` once per effective file and surfaces intro, recap, and credits in `[start_seconds, end_seconds)` (ignoring previews). Missing, failed, or mismatched responses omit Skip while leaving playback and manual seeking usable. Up reaches Skip, Down/Back returns to transport, Enter/Play seeks to the segment end, and the countdown is informational only (never auto-seeks).
- **Subtitle sync (`subtitleSync.ts`):** requires `external` on status (older servers read as unavailable); Reset Timing sends `If-Match` from the subtitle's `ETag` ([subtitle-sync.md](../../../docs/playback/subtitle-sync.md)).
- **Ratings, requests, trailers, calendar, trickplay, and person (`ratings.ts`, `requests.ts`, `trailers.ts`, `calendar.ts`, `trickplay.ts`, `person.ts`):** `getRatingsCapability` counts only `state: "available"` (`shownRatingSources`); `requests.ts` defaults optional `remove_failed_supported` to `false` (non-boolean fails); `calendar.ts` preserves server day groups and event order with no pagination or local access filtering; `decodePerson` validates optional `photo_thumbhash` and preserves calendar date strings ([calendar.md](../../../docs/features/calendar.md), [person-filmography.md](../../../docs/features/person-filmography.md#hero-and-portrait), [requests.md](../../../docs/features/requests.md), [details-actions.md](../../../docs/features/details-actions.md), [seek-thumbnails.md](../../../docs/playback/seek-thumbnails.md)).
- **Watch Together (`watchTogether.ts`):** decodes HTTP v2 bodies and `silo.room.v2` socket frames (socket frames are modeled from `internal/watchtogether/service.go` and `internal/api/handlers/watch_together.go`, not `openapi.json`). Numeric socket IDs normalize to strings; timestamps decode to epoch ms; `suggestions_update` strips `voted_by_me`, so viewer votes come only from HTTP `suggestions`. Never log or store `room_access_token`. Suggestion delete, member state, and source fallback remain unimplemented ([watch-party.md](../../../docs/features/watch-party.md)).
